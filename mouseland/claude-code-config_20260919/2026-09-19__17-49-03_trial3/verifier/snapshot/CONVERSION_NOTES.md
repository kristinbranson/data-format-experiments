### Notes
- Neural data are **deconvolved** Suite2p traces (`spks`), stored as a list of 3 sub-arrays
  (imaging planes/slices) that are concatenated along the neuron axis. No ΔF/F needs to be
  computed — the paper states "All our analyses were based on deconvolved fluorescence traces".
- No spike-sorting quality filtering exists (this is imaging, not ephys). Suite2p's own cell
  classifier has already been applied upstream. The only neuron curation in the reference code
  is **anatomical**: keep neurons assigned to a visual area (`iarea ∉ {−1, 7}`).
- The reference code **truncates behaviour to the number of neural frames**: `nfr = spk.shape[1]`,
  then `beh['ft_*'][:nfr]`. The behaviour arrays are 1 frame longer than the imaging arrays.
- The reference never normalises `spks` before analysis (it uses d′, which is scale-free).
- `data_process_script.ipynb` documents every `beh` field (copied into Step 2 below).

### Processing Details
- Temporal alignment for the decoder task: **trial start = corridor entry**
  (`Trial_start_time`, i.e. the frame at which `ft_trInd` becomes the trial index and
  `ft_Pos` restarts at 0).
- Temporal binning: **native imaging frames** (3.1777 Hz → 314.7 ms). The reference code only
  re-bins onto *position* (60 bins of 1 dm) for its tuning-curve figures; a decoder that must
  predict position from neural activity has to stay in the time domain, so the native frame
  grid is used here.
- The paper's own quantifications (d′, coding direction) use raw deconvolved traces restricted
  to `ft_CorrSpc & (ft_move > 0)`.

### Curation Steps

**Session/mouse curation rules**: none — all 89 recordings from all 19 mice are analysed in the
paper (different figures use different subsets, but the union is all 89).

**Neuron curation rules**:
- Suite2p ROI detection + cell classification + neuropil correction + deconvolution (upstream).
- Keep neurons assigned to a visual area: `iarea ∉ {−1, 7}` (`Get_density_map`, utils.py:409).
- No activity-based threshold is used in the reference.

**Trial curation rules**:
- No trial-level exclusions in the main analyses. Individual figures apply extra criteria
  (e.g. Fig. 4j uses only rewarded trials with a first lick after 2 m), but these are
  figure-specific and not part of the general pipeline.
- Timepoint-level exclusion: outside 0–4 m, or VR not moving (mouse not running).

### Key Decisions
1. **All 89 recordings / 19 mice are kept.** The paper analyses all of them; no session-level
   quality criterion exists in code or text.
2. **Timepoints: `(ft_move>0) & ft_CorrSpc`.** Identical to `fr_valid` in
   `Get_dprime_selective_neuron` and to the Methods ("0–4 m region", "excluded the data points
   in which the animal was not running"). It also removes the reward-collection stops, exactly
   as the paper intends.
3. **Native imaging frames as time bins** (314.7 ms; frame rate varies by <0.4 % across
   sessions, so a single `time_bin_size` is reported). No re-binning — the imaging rate is
   already slow, and the paper's only re-binning is onto position, which cannot be used when
   position is a decoder target.
4. **Neurons: visual-cortex only (`iarea ∉ {−1,7}`), then a seeded random subsample of up to
   2000 per session, stratified proportionally over V1/mHV/lHV/aHV.**
   Rationale: 4.1 M visual neurons × 821 k timepoints is ~150 GB and would make both the pickle
   and the 200-epoch decoder training intractable (every epoch copies the whole dataset to the
   GPU). 2000 is exactly `decoder.train_decoder`'s `svd_max_neurons` default, so the SVD
   initialisation is computed on the true neurons rather than on a random Gaussian projection.
   Stratifying keeps each session's area composition. Seeded → reproducible.
5. **Neural activity is z-scored per neuron** over the retained timepoints of its session.
   Deconvolved Suite2p amplitudes are in arbitrary, wildly heterogeneous units (per-neuron s.d.
   spans 0.5 – 350 within one session; values up to 2849). The decoder initialises its
   projection with an **uncentred** SVD and then feeds the projections straight into a linear
   layer at lr = 1e-3, so raw amplitudes produce saturated logits. Z-scoring makes the SVD a
   true PCA and is the standard preprocessing for deconvolved traces in this lab's pipelines.
   This is the one deliberate deviation from the reference, required by "training a neural
   decoder"; it is a per-neuron affine rescaling and therefore changes no relative structure.
6. **Reward availability = rewarded *corridor*, not reward delivered** (see Step 4). Prevents
   leaking the licking output into the decoder input.
7. **Stimulus = canonical role id** (0 circle1, 1 circle2, 2 leaf1, 3 leaf2, 4 leaf3,
   5 leaf1_swap1, 6 leaf1_swap2, 7 circle3). Pools rock/brick mice onto the leaf/circle roles
   exactly as the paper does, giving one label set that means the same thing in every session.
8. **Time inputs clipped to ±30 s.** Wall-clock time is used (not "running time"), because that
   is the true time since corridor entry and because running-frame counts would make position
   a deterministic function of the input. ~2 % of retained samples come from trials in which the
   mouse paused for tens of seconds inside the corridor (max 400 s); clipping keeps the linear
   decoder well conditioned without discarding any data.
9. **Running-speed bins from global quartiles** — the spec says each bin should hold 25 % of
   the data, which is only exactly true if the quantiles are computed over the pooled dataset.
10. **No trials are dropped.** Every one of the 38,110 trials has ≥1 retained frame (verified).

`WallName[isRew][0]` rewarded-stimulus rule from `get_cat_id`, and the
`beh['LickFr'].astype(int)` event-frame convention from `spk_2_firstLick`.

**Code inefficiencies identified**
- Reading 405 GB of `spk` files is the only real cost. Single-threaded `np.load` runs at
  ~1.2 GB/s.
- A first version concatenated all planes and then subset, doubling peak RAM per session
  (up to ~20 GB).
- A first version computed the retained-frame mask from `len(ft)-1`; the true frame count
  comes only from the spk file and is not always `len(ft)-1` (e.g. `TX109_2023_04_18_1`
  has 17,371 frames vs `len(ft)-1 = 17,372`). This could have silently mis-sliced trials.

**Code speedups / fixes added**
- 6 worker processes reading in parallel → measured **5.8 GB/s** aggregate (vs 1.2 GB/s),
  so the whole 405 GB is read in ~75 s.
- Only the 2000 selected rows and the retained columns are materialised
  (`p[sel][:, keep_idx]` per plane), so peak RAM per worker is the mmap'd file plus
  ~0.2 GB instead of two full copies.
- Neural work is done **before** any trial slicing, so the true `nfr` from the spk file
  drives every mask; the main process asserts that its own mask matches the worker's.
- Behaviour files are read once each (1.1 s total) and reduced to ~16 arrays per session.
- `mean`/`std` accumulated in float64 (float32 accumulation over ~10⁴ terms shifted
  individual z-scores by up to 2×10⁻³).

   |---|---|---|---|---|---|
   | 1000 | 0.8324 | 0.8042 | 0.8444 | 0.5792 | 0.779 / 0.579 = 1.35 |
   | **2000 (chosen)** | **0.8731** | 0.7636 | **0.8936** | 0.5695 | 0.937 / 0.570 = 1.64 |
   | 4000 | 0.3025 | 0.7305 | 0.5638 | 0.3576 | 1.00 |

   Halving the neuron count removes most of the speed gap but costs 4–5 accuracy points on
   stimulus and position and only buys 1 point of speed accuracy, so 2000 was kept.
   4000 is catastrophically worse for a mechanical reason: above `svd_max_neurons = 2000`,
   `decoder.train_decoder` initialises the projection through a random Gaussian matrix
   (`P ~ N(0,1)`, shape `n_neurons × 2000`) instead of the true SVD, which inflates the
   initial projection norm — the training loss plateaus around 12 instead of 0.15. This is
   independent confirmation that 2000 neurons/session is the right operating point.
3. **The residual gap is intrinsic.** Running speed at 3.18 Hz is a fast, continuous
   variable quantised into quartiles; adjacent quartiles differ by only a few cm s⁻¹
   (edges 12.4 / 25.4 / 40.9 cm s⁻¹), so a large share of the errors are off-by-one-bin.
   The decoder trains for a fixed 200 epochs with no early stopping, so some memorisation
   of the 178,000 projection parameters is unavoidable; validation accuracy is nevertheless
   2.3× chance.
