# Decisions

## 1-a. How are **all the data** for all subjects, sessions, and trials loaded in?

i. The agent reads the local project experiment CSV, inventories locally present `behavior_ophys_experiment_*.nwb` files, joins them by `ophys_experiment_id`, excludes passive experiments, and opens each retained NWB directly with `h5py`. It does not use the AllenSDK cache or load unavailable experiments.

ii.
```python
exp_table = pd.read_csv(table_path)
available_files = {
    int(path.stem.split("_")[-1]): path
    for path in sorted(experiment_dir.glob("behavior_ophys_experiment_*.nwb"))
}
exp_table = exp_table[exp_table["ophys_experiment_id"].isin(available_files)].copy()
exp_table = exp_table[~exp_table["passive"]].copy()
...
with h5py.File(session.filepath, "r") as f:
```

iii. The notes say direct HDF5 access was chosen because the installed AllenSDK/NWB stack could not instantiate these NWBs. Active local experiments were selected because passive viewing is not the requested active task and has degenerate outcomes.

## 1-b. How are the data split into subjects?

i. Subjects are unique string-valued `mouse_id`s among pass-1 retained experiment files; each converted session receives the corresponding index.

ii.
```python
subjects = sorted({session.mouse_id for session in kept_sessions})
subject_to_idx = {subject: idx for idx, subject in enumerate(subjects)}
...
subject_idx[idx - 1] = subject_to_idx[session.mouse_id]
```

iii. The notes identify `mouse_id` in the experiment metadata as the subject identifier.

## 1-c. How are the data split into sessions?

i. Every retained `ophys_experiment_id` NWB is treated as a separate converted session, sorted by experiment ID. Simultaneously acquired planes sharing an `ophys_session_id` are not merged.

ii.
```python
for row in exp_table.itertuples(index=False):
    sessions.append(SessionMeta(
        ophys_experiment_id=int(row.ophys_experiment_id),
        ophys_session_id=int(row.ophys_session_id),
        ...
        filepath=available_files[int(row.ophys_experiment_id)],
    ))
```

iii. The agent justified this as matching the `BehaviorOphysExperiment` object/file granularity and producing one imaging plane and region per converted session.

## 1-d. How are the data split into trials?

i. Trials come from the processed NWB `intervals/trials` table. Each kept trial spans its `start_time` to `stop_time`; a 30 Hz grid of bin centers is constructed within those variable-length bounds.

ii.
```python
trials = read_interval_table(f["intervals"]["trials"], columns)
...
n_bins = max(1, int(np.ceil((stop_time - start_time) / DT)))
centers = start_time + (np.arange(n_bins, dtype=np.float64) + 0.5) * DT
```

iii. The agent regarded the NWB trial table as the authoritative Allen-processed trial definition and used full trial bounds so all time-varying outputs could be represented.

## 1-e. How are trials filtered based on quality controls?

i. Only `go` or `catch` trials are retained; aborted and auto-rewarded trials are removed. Sessions with fewer than two such trials, empty task presentations, or missing required eye tracking are skipped. Invalid time intervals are skipped in conversion.

ii.
```python
trials = trials[(trials["go"] | trials["catch"]) &
                (~trials["aborted"]) &
                (~trials["auto_rewarded"])].copy()
if len(trials) < 2:
    continue
...
if centers.size == 0:
    continue
```

iii. This follows the instruction to include contingent go/catch trials and exclude aborted/free-reward trials; two trials are required by the target format.

## 2-a. What variables in the raw data is the `neural` data derived from?

i. Neural activity is taken from the NWB event-detection timestamps and event magnitude matrix, not from dF/F.

ii.
```python
event_group = f["processing"]["ophys"]["event_detection"]
timestamps = np.asarray(event_group["timestamps"][:], dtype=np.float64)
events = np.asarray(event_group["data"][:], dtype=np.float32)
```

iii. The agent chose detected calcium events because the paper's neural analyses used events and stated that the traces were already generated by the reference pipeline.

## 2-b. How is the `neural` data processed?

i. The time-by-cell event matrix is linearly interpolated onto each trial's uniform 30 Hz bin centers and transposed to cells by time. No additional smoothing or normalization is applied.

ii.
```python
idx_hi = np.searchsorted(src_time, dst_time, side="left")
...
interp = src_value[idx_lo] * (1.0 - w[:, None]) + src_value[idx_hi] * w[:, None]
return interp.T.astype(np.float32, copy=False)
```

iii. A common 30 Hz grid was intended to reconcile native 31 Hz and 11 Hz recordings and to match the paper's event-triggered interpolation convention.

## 2-c. How is the `neural` data filtered based on quality controls?

i. No explicit cell filtering occurs in the converter. Cell count is read from the NWB cell specimen table, relying on upstream NWB/Allen processing to have excluded invalid ROIs. Sessions may be excluded for session/trial/eye-data reasons.

ii.
```python
cell_table = f["processing"]["ophys"]["image_segmentation"]["cell_specimen_table"]
n_cells = len(cell_table["cell_specimen_id"])
```

iii. The notes state that invalid, duplicate, motion-corrupted, dendritic, and otherwise poor ROIs were curated upstream by the SDK pipeline.

## 2-d. How is the per-trial `neural` data aligned to the event described in the `instructions`?

i. Neural data is aligned to trial start in absolute experiment time. Trial-bin centers run from `start_time + DT/2` until `stop_time`, and event traces are interpolated onto those centers.

ii.
```python
centers = build_trial_bins(float(trial["start_time"]), float(trial["stop_time"]))
neural_trial = linear_resample_matrix(ophys_time, events, centers)
...
"temporal_alignment_event": "trial start",
```

iii. The notes say all streams were first related through absolute, ophys-referenced timestamps and then cut into trials.

## 2-e. What is the temporal resolution (time bin size) of the converted data? Is any temporal rebinning applied?

i. The output is uniformly sampled at 30 Hz, or 33.333 ms per bin. Neural and behavioral streams are linearly resampled, so temporal rebinning/interpolation is applied.

ii.
```python
DT = 1.0 / 30.0
TIME_BIN_MS = DT * 1000.0
...
"time_bin_size": TIME_BIN_MS,
```

iii. The agent chose this to enforce an identical bin size across mixed native frame rates and cited 30 Hz interpolation in the paper.

## 3-a. What variables in the raw data is `output` *Image identity* derived from?

i. Image identity comes from task stimulus-presentation interval tables: `image_name`, `start_time`, `stop_time`, `omitted`, `trials_id`, and `stimulus_block_name`.

ii.
```python
columns = ["start_time", "stop_time", "image_name", "omitted",
           "is_change", "trials_id", "stimulus_block_name", ...]
```

iii. The agent preferred per-flash presentations over trial-level initial/change fields because they encode the exact flash and gray/omission sequence.

## 3-b. What processing is involved in computing `output` *Image identity*?

i. Global image names are sorted and integer-encoded, with `gray` forced to code 0. Every trial begins as gray; bins falling within a non-omitted flash receive its image code, while omitted flashes remain gray.

ii.
```python
image_identity = np.full(centers.shape[0], image_value_to_idx["gray"], dtype=np.int64)
...
if bool(row.omitted) or str(row.image_name) == "omitted":
    image_identity[mask] = image_value_to_idx["gray"]
else:
    image_identity[mask] = image_value_to_idx[str(row.image_name)]
```

iii. The notes explicitly encode gray/omission periods because they occupy trial time and the requested identity applies during non-gray screens.

## 3-c. How is `output` *Image identity* aligned with the neural data?

i. Presentation start/stop intervals are masked against the same 30 Hz `centers` used for neural interpolation.

ii.
```python
mask = (centers >= float(row.start_time)) & (centers < float(row.stop_time))
image_identity[mask] = image_value_to_idx[str(row.image_name)]
```

iii. A common absolute-time grid guarantees a one-to-one output/neural bin correspondence.

## 4-a. What variables in the raw data is `output` *Image change* derived from?

i. Image change is derived from the stimulus-presentation `is_change` flag and each presentation's time interval and trial ID.

ii.
```python
trial_presentations = presentations[presentations["trials_id"] == int(trial["id"])].copy()
...
if bool(row.is_change):
    image_change[mask] = 1
```

iii. The notes identify `is_change` as the reference presentation-level change annotation, with trial `change_time` used conceptually for checks.

## 4-b. What processing is involved in computing `output` *Image change*?

i. A zero vector is created and bins covered by any presentation marked `is_change` are set to one.

ii.
```python
image_change = np.zeros(centers.shape[0], dtype=np.int64)
...
if bool(row.is_change):
    image_change[mask] = 1
```

iii. This represents the change only for the change-image flash rather than for all post-change time.

## 4-c. How is `output` *Image change* thresholded into categories?

i. It is already binary: 0 is `no_change`, 1 is `change`; no numeric threshold is estimated.

ii.
```python
"output_values": [
    ...
    ["no_change", "change"],
]
```

iii. The underlying NWB `is_change` annotation is boolean, so direct categorical encoding is sufficient.

## 4-d. How is `output` *Image change* aligned with the neural data?

i. The change-presentation interval is tested against the same trial centers used to interpolate neural data.

ii.
```python
mask = (centers >= float(row.start_time)) & (centers < float(row.stop_time))
if bool(row.is_change):
    image_change[mask] = 1
```

iii. The shared 30 Hz absolute-time grid provides alignment.

## 5-a. What variables in the raw data is `output` *Running speed* derived from?

i. Running speed uses NWB `processing/running/speed/data` and its timestamps.

ii.
```python
running_group = f["processing"]["running"]["speed"]
timestamps = np.asarray(running_group["timestamps"][:], dtype=np.float64)
speed = np.asarray(running_group["data"][:], dtype=np.float64)
```

iii. This is the SDK-produced filtered wheel speed in physical units.

## 5-b. What processing is involved in computing `output` *Running speed*?

i. Speed is linearly interpolated onto trial centers. A first pass pools all included trial samples to calculate global five-quantile edges; the second pass digitizes the values.

ii.
```python
running_trial = linear_resample_vector(running_time, running_speed, centers)
...
running_edges = compute_quantile_edges(running_all[np.isfinite(running_all)], 5)
running_bin = digitize_with_edges(running_trial, running_edges)
```

iii. Global quantiles keep category meanings consistent and approximately balance classes.

## 5-c. How is `output` *Running speed* thresholded into categories?

i. Four interior edges of five global equal-percentile bins define labels 0–4 (`q1`–`q5`). Values are clipped to the observed global edge range before `searchsorted`.

ii.
```python
edges = np.quantile(values, np.linspace(0.0, 1.0, nbins + 1))
clipped = np.clip(values, edges[0], edges[-1])
bins = np.searchsorted(edges[1:-1], clipped, side="right")
```

iii. Equal-frequency bins satisfy the requested five percentile bins and aid balanced decoding.

## 5-d. How is `output` *Running speed* aligned with the neural data?

i. Running speed is interpolated at precisely the same 30 Hz trial centers as neural activity.

ii.
```python
neural_trial = linear_resample_matrix(ophys_time, events, centers)
running_trial = linear_resample_vector(running_time, running_speed, centers)
```

iii. Hardware-synchronized absolute timestamps and shared destination times provide alignment.

## 6-a. What variables in the raw data is `output` *Pupil diameter* derived from?

i. It uses eye-tracking timestamps plus pupil ellipse `width` and `height` from `acquisition/EyeTracking/pupil_tracking`.

ii.
```python
timestamps = np.asarray(eye_group["eye_tracking"]["timestamps"][:], dtype=np.float64)
width = np.asarray(eye_group["pupil_tracking"]["width"][:], dtype=np.float64)
height = np.asarray(eye_group["pupil_tracking"]["height"][:], dtype=np.float64)
diameter = 2.0 * np.maximum(width, height)
```

iii. The agent interpreted ellipse axes as radii and used twice the larger axis as pupil diameter.

## 6-b. What processing is involved in computing `output` *Pupil diameter*?

i. Diameter is computed as `2*max(width,height)`, nonfinite samples are interpolated over eye time, the result is interpolated onto trial centers, and global five-quantile edges are computed and applied. Sessions without EyeTracking are dropped.

ii.
```python
diameter = fill_nan_by_time(timestamps, diameter)
pupil_trial = linear_resample_vector(pupil_time, pupil_diameter, centers)
pupil_edges = compute_quantile_edges(pupil_all[np.isfinite(pupil_all)], 5)
```

iii. The notes describe filling blink-related gaps within sessions and excluding sessions where the stream is wholly unavailable.

## 6-c. How is `output` *Pupil diameter* thresholded into categories?

i. It uses the same global equal-percentile procedure as running speed, yielding codes 0–4 (`q1`–`q5`).

ii.
```python
pupil_bin = digitize_with_edges(pupil_trial, pupil_edges)
PUPIL_BIN_NAMES = [f"q{i}" for i in range(1, 6)]
```

iii. Global bins provide consistent labels and approximately equal class counts.

## 6-d. How is `output` *Pupil diameter* aligned with the neural data?

i. The processed pupil series is interpolated at the same 30 Hz trial centers as neural activity.

ii.
```python
neural_trial = linear_resample_matrix(ophys_time, events, centers)
pupil_trial = linear_resample_vector(pupil_time, pupil_diameter, centers)
```

iii. Shared absolute timestamps and destination bin centers provide alignment.

## 7-a. What variables in the raw data is `output` *Trial outcome* derived from?

i. Outcome comes from the trial-table booleans `hit`, `miss`, `false_alarm`, and `correct_reject`.

ii.
```python
if bool(trial_row["hit"]): return 0
if bool(trial_row["miss"]): return 1
if bool(trial_row["false_alarm"]): return 2
if bool(trial_row["correct_reject"]): return 3
```

iii. These are the canonical mutually exclusive outcomes for retained contingent trials.

## 7-b. What processing is involved in computing `output` *Trial outcome*?

i. The first true outcome in a fixed order is mapped to 0–3; absence of a valid outcome raises an error. The code is repeated across every time bin of that trial.

ii.
```python
outcome_idx = trial_outcome_index(trial)
outcome_trace = np.full(centers.shape[0], outcome_idx, dtype=np.int64)
```

iii. Repetition gives every output a consistent `(n_output, T)` representation while remaining static per trial.

## 8. How are minor mistakes in the data, e.g. missing data, handled?

i. Missing local files never enter the inventory; passive sessions are excluded; missing EyeTracking and empty task presentations cause session exclusion; pupil NaNs are time-interpolated (edge gaps receive nearest finite values); all-NaN pupil data, invalid outcomes, or too few converted trials raise errors. Degenerate quantile edges are separated by machine epsilon. Invalid trial bounds are skipped. Pass 1 catches `KeyError`, but most pass-2 errors are not caught.

ii.
```python
if "EyeTracking" not in f["acquisition"]:
    raise KeyError("Missing EyeTracking acquisition")
...
values[~finite] = np.interp(time_axis[~finite], time_axis[finite], values[finite])
...
except KeyError as exc:
    print(f"... skip ... {exc}")
```

iii. The agent aimed to retain sessions with modest blink-related gaps, exclude streams that cannot support the requested output, and fail on ambiguous outcome/neural conditions rather than silently invent labels.

## 9-a. What are the most time-consuming steps of the code?

i. Disk I/O and reading each large NWB/event matrix dominate. The two-pass design opens every retained file twice; neural interpolation and optional plotting add computation.

ii.
```python
running_edges, pupil_edges, kept_sessions, image_names = collect_global_statistics(sessions)
...
neural_trials, output_trials, brain_region_idx = convert_session(...)
```

iii. The notes explicitly identify NWB event-matrix I/O and the required second pass as the principal costs.

## 9-b. What loops in the code could have been vectorized to improve efficiency?

i. The loops over trials and stimulus presentations, string decoding, metadata-row construction, and pass-1 per-trial interpolation could potentially be batched/vectorized. Neural interpolation itself is already vectorized across cells.

ii.
```python
for trial_idx, trial in trials.iterrows():
    ...
    for row in trial_presentations.itertuples(index=False):
        ...
```

iii. The agent notes that vectorized `searchsorted` and broadcasting avoided the much more expensive per-neuron interpolation loop; it retained trial/presentation loops for variable-length data and clarity.

## 9-c. What processing does the code repeat multiple times?

i. Trial-table parsing, presentation extraction, running loading, pupil loading/filling, trial-grid construction, and behavioral interpolation are repeated in pass 1 and pass 2. Each NWB is reopened in both passes.

ii.
```python
# pass 1
with h5py.File(session.filepath, "r") as f:
    trials = get_trial_table(f)
    presentations = get_task_presentations(f)
    running_time, running_speed = get_running_data(f)
    pupil_time, pupil_diameter = get_pupil_data(f)
# pass 2 repeats these calls in convert_session
```

iii. The two-pass streaming design trades repeated I/O/processing for global quantile thresholds without retaining the full dataset in memory.

## 9-d. What unnecessary processing does the code do that is discarded in downstream analyses?

i. Pass 1 reads and filters stimulus presentations mainly to collect image names, then discards them; it constructs every trial grid and interpolates behavioral data that are recomputed in pass 2. The optional diagnostic path also computes/plots raw windows that are not saved in the dataset. `math` is imported but unused.

ii.
```python
presentations = get_task_presentations(f)
image_names.update(...)
...
running_trial = linear_resample_vector(...)
pupil_trial = linear_resample_vector(...)
```

iii. These costs follow from global vocabulary/quantile collection and optional validation; only the repeated pass-1 intermediate arrays are discarded after contributing summary statistics.
