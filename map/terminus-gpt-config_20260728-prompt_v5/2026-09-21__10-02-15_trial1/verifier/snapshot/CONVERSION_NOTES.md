### Notes
- Repository is primarily for video/ephys analyses on the MAP dataset; core reusable code is in `VideoAnalysisUtils`, with batch scripts in `Sherlock` and exploratory notebooks elsewhere.
- Processed ephys sessions used by downstream analyses are generated by `preprocessing_DJ_2022Aug.py` and loaded by `population_decoding_utils.load_session`.
- Trial curation in reference decoding code uses `get_regular_trial_mask`, excluding early-lick, auto-water, free-water, no-response (`correctness == -1`), and stimulation trials.
- Cross-modal alignment with video/embeddings uses `temporal_alignment_embed_and_ephys` at `dt=0.0034` s.
- The Sherlock preprocessing script appears to be the strongest reference for the method paper's ephys preprocessing parameters: 40 ms spike-count window, 3.4 ms stride, aligned from -3 to +3 s around task events, with neuron QC mode `classifier`.
- Because our decoder task differs, we will likely need to re-bin to 50 ms bins and align to go cue while preserving reference neuron/trial curation logic where applicable.
- Need to inspect raw data structure next (Step 2) to determine which preprocessed/raw files are available in `/app/data` and whether we should reproduce preprocessing from raw spikes or use already processed session files.

## Step 2: Dataset Exploration
**Status**: COMPLETE

### Data Structure
- `/app/data` contains NWB files organized by subject folders: `sub-<subject_id>/sub-<subject_id>_ses-<timestamp>_behavior+ecephys+ogen.nwb`.
- Each NWB session file contains an `intervals/trials` table and a `units` table.
- Trial table fields observed include: `start_time`, `stop_time`, `trial`, `photostim_onset`, `photostim_power`, `photostim_duration`, `trial_uid`, `task`, `task_protocol`, `trial_instruction`, `early_lick`, `outcome`, `auto_water`, `free_water`.
- Unit table fields observed include spike times plus many QC metrics and annotations: `unit_quality`, `avg_firing_rate`, `isi_violation`, `presence_ratio`, `amplitude_cutoff`, `classification`, `anno_name`, `is_good_trials`, `spike_times`, `waveform_mean`, etc.
- The dataset is native NWB/HDF5 electrophysiology + behavior + optogenetics data; photostimulation variables are present in the trial table.
- Brain region information appears to be stored via unit annotation fields such as `anno_name` rather than a dedicated `brain_region` column.

### Processing Details
- Behavioral task is a memory-guided directional licking task with sample, delay, response structure.
- Early lick trials and no-response trials were excluded for many analyses in the papers.
- Photoinhibition ended before the Go cue; this is important for go-cue alignment and photostim input construction.
- Reference code for the later method paper uses classifier-based unit QC and trial masking for regular/control trials.
- For our conversion, decoder alignment must be to Go cue with a [-2.5 s, +1.5 s] window and 50 ms bins, which differs from some reference analysis windows but should preserve source event timing and curation logic where applicable.

### Curation Steps

**Neuron curation rules**:
- Papers/white paper describe region-specific logistic-regression classifiers trained on 15 QC metrics to label units as good vs unlabeled.
- Reference code indicates `qc_mode='classifier'` should be treated as the default intended curation.

**Trial curation rules**:
- Exclude early lick and no-response trials for many analyses in the papers.
- Reference decoding helper additionally excludes auto-water, free-water, and stimulation trials when defining regular control trials.

## Step 5: Mapping Planning
**Status**: COMPLETE

### Variable Mapping
| Source Variable | Target Field | Transform | Reference Code Function(s) | Notes |
|-----------------|--------------|-----------|----------------------------|-------|
| `units/spike_times` for units with `classification == 'good'` | neural | Bin spike times into 50 ms spike counts or rates over [-2.5, +1.5] s relative to `BehavioralEvents/go_start_times` for each trial | `sliding_histogram`, `process_one_sess`, `process_one_area` | Use paper-consistent classifier QC, but task-required 50 ms bins and go-cue alignment |
| `BehavioralEvents/sample_start_times` (tone/sample onset) and go cue times | input[0] | Continuous time-from-tone-onset per bin: for each trial/bin, `bin_center_abs_time - sample_onset_time`; optionally negative before onset | Event alignment logic inferred from NWB event timeseries | Decoder task explicitly requests time from tone onset in seconds |
| `BehavioralEvents/photostim_start_times` and `photostim_stop_times` or trial photostim fields | input[1] | Binary time-varying photostim on/off per bin within each aligned trial window | Reference regular-trial mask uses stimulation variable | Need to handle sessions/trials with `N/A` in trial table by using event timeseries |
| `trial_instruction` + lick event times (`left_lick_times`, `right_lick_times`) + `outcome` | output[0] choice | Per-trial categorical label: left / right / no lick | Trial curation logic + lick event streams | If no post-go lick in window or outcome ignore, assign no lick; otherwise infer first lick direction or instructed/correct side as needed |
| `outcome` | output[1] outcome | Map string labels to categorical ignore / miss / hit | NWB trial table | Direct per-trial categorical output |
| `early_lick` | output[2] early lick | Map string labels to categorical no / yes | NWB trial table | Direct per-trial categorical output |
| `BehavioralTimeSeries/Camera0_side_TongueTracking/data` and timestamps | output[3] tongue y-position | Align tracking to trial bins; use y coordinate and session-wide 40th/60th percentiles to discretize into 0/1/2; use class 3 when tongue not visible based on tracking confidence/likelihood | Video alignment concepts in `temporal_alignment_embed_and_ephys` | Need to determine coordinate column order; likely x,y,likelihood with low likelihood => not visible |
| `subject.subject_id` / folder name | subjects, subject_idx | Collect unique subject IDs and session-to-subject mapping | NWB metadata | One subject per NWB folder |
| `units/anno_name` | brain_regions, brain_region_idx | Use annotation strings as region labels; map each neuron to unique region string | Reference code uses anatomical labels/area subsets | Preserve native labels unless later coarsening is justified |

### Key Decisions
1. **Neuron curation**: Use `classification == 'good'` as the primary neuron filter because this reproduces the paper's reported good-unit count (~69.5k vs 69.9k reported) and matches `qc_mode='classifier'` in reference code.
2. **Temporal alignment**: Align all trials to `BehavioralEvents/go_start_times` because the decoder task explicitly requires go-cue alignment.
3. **Binning**: Use 50 ms bins from -2.5 s to +1.5 s around go cue, overriding the paper code's finer 3.4 ms stride / 40 ms window because the decoder task specifies this.
4. **Trial inclusion**: Retain all trials with valid go cue and sufficient data for the requested outputs, rather than only regular control trials, because the decoder must predict photostimulation and behavioral variables across the dataset. We will still document masks for paper-style regular-trial analyses.
5. **Choice definition**: Define choice from actual lick behavior when possible (left/right lick times after go cue); assign `no lick` when no lick is observed in the response period or outcome is ignore.
6. **Outcome and early lick**: Use direct categorical trial-table labels without collapsing categories.
7. **Tongue visibility/discretization**: Use session-wide tongue-y percentiles (40th, 60th) over visible frames only; assign class 3 when tracking confidence indicates not visible.
8. **Brain region labels**: Use native `anno_name` labels from NWB for maximum fidelity; can later derive coarser labels if needed, but preserve originals in converted dataset.

## Step 10: Critical Review 1
**Status**: COMPLETE

### Checks Performed
1. Output log verification: initial full verification found NaN/Inf inputs; fixed by robust tone-onset fallback.
2. Output log verification iteration 2: found many all-zero neural trials in one session; traced to trial validity mismatch (`is_good_trials` had fewer columns than go-cue trials).
3. Trial validity review: filtered trials to those covered by `is_good_trials` and dropped any residual all-zero neural trials.
4. Re-verification: sample verify-only clean; final full verify-only clean with no warnings/errors.

### Issues Found and Resolved
- Missing tone/sample onset for some trials caused NaN input values: replaced NaN with robust nearest-preceding sample-onset matching and finite fallback (~0.6 s before go cue).
- Many late trials in some sessions had all-zero neural data: discovered that raw NWB `is_good_trials` covered only a subset of trials (e.g. 160 valid neural trials for a 480-go-cue session). Resolved by filtering to valid trial columns and dropping any residual all-zero neural trials.
- Performance regression from per-trial spike extraction: mitigated by caching spike times per good unit once per session.
